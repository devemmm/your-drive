Problems in the current layout

  1. Top-level screens use a back arrow. Wallet / Chat / Profile / Post a Ride / Rent a Car / Hire a Driver are conceptually peers of Home, but their header back arrow just calls router.replace("/(drawer)"). The hamburger disappears as soon as you leave Home.
  2. Drawer hides what the drawer is for. My Rides, Post a Ride, Chat, Profile are declared in the drawer with drawerItemStyle: display:none, then re-listed inside DrawerContent.tsx. The two lists drift.
  3. Home is not in the drawer menu. Once you leave Home, the only way back is the wallet's back arrow → which works but contradicts the hamburger pattern.
  4. No driver inbox shortcut. /ride-request/open exists but is only reached from Profile → "View open ride requests". It should be a first-class entry for drivers.
  5. Map ignores theme. HomeScreen renders a MapView with no customMapStyle, so in dark mode the map stays light.
  6. Drawer header reads white in dark mode. Likely the SafeAreaView top inset on the drawer is not painted with colors.background (or the status bar style isn't reacting to resolved).

Proposed navigation

Every destination reachable from the drawer becomes a true top-level stack inside (drawer). The header on the root of each top-level stack shows the hamburger; child screens push onto that stack and show a real back arrow (navigation.pop()).

Rules

  1. Hamburger ↔ Back. Header shows the hamburger iff the route is the root of a drawer stack. Otherwise it shows back and runs navigation.pop() (or router.back()).
  2. Single source of truth for the drawer menu. Drop the drawerItemStyle: display:none hack and declare each drawer stack once with the right drawerLabel + icon.
  3. Role decides what "home" is. The home/ stack picks MapHome for passengers and LiveRequestsHome for drivers (gated on user.isDriverOnboarded && user.isAvailableForRideRequest). Drivers also get a second drawer item "Map" so they can still browse the passenger map.
  4. One ScreenHeader, two modes. Add a variant="root" | "child" prop to ScreenHeader. Root opens the drawer; child pops the stack. No more passing onBack manually.

Dark mode fixes (bundled)

  1. Google Map theme. Pass customMapStyle to MapView based on useTheme().resolved. Ship a small mapStyle.dark.json (e.g. the Snazzy Maps "Night" style) alongside the existing map config.
  2. Drawer top-strip. The white slab is the SafeAreaView top inset bleed-through. Set the drawer screen's drawerStyle.backgroundColor to colors.background and wrap DrawerContent in a View with colors.background behind the SafeAreaView. Also swap the StatusBar style on theme change.

  8. Promote (drawer)/index.tsx from a single screen to a (drawer)/home/ stack with a role-aware index.tsx.

Components

  1. ScreenHeader gains variant: "root" | "child". Default child. root renders ☰ and calls navigation.openDrawer().
  2. Remove every onBack={() => router.replace("/(drawer)")} in the moved screens.
  3. DrawerContent.tsx stops hand-listing menu items — it iterates over the routes that the drawer navigator exposes via props.state.routes, with metadata (icon, label, role gate) co-located on each Drawer.Screen.
  4. New MapStyleProvider (or just a small useMapStyle()) picks light/dark JSON based on useTheme().resolved.
